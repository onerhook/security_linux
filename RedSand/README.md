# 🏜️ RedSand Secure - Система Анализа Вредоносного ПО с ML

## 📋 Описание

**RedSand Secure** - это современная система безопасности для анализа и обнаружения вредоносного программного обеспечения. Проект сочетает в себе статический анализ, эвристическое сканирование, машинное обучение и поведенческий анализ для выявления угроз с минимальным количеством ложных срабатываний.

---

## 🚀 Ключевые Особенности

### 🔍 Многоуровневая Система Обнаружения

1. **Статический Анализ (VirusScanner)**
   - Проверка SHA256 хешей по базе известных угроз
   - Поиск явных вредоносных сигнатур в коде (70+ паттернов)
   - Обнаружение подозрительных паттернов (15+ эвристик)
   - Анализ PE-файлов (для Windows исполняемых файлов)
   - Извлечение и анализ строк из файлов

2. **Машинное Обучение (ML Classifier)**
   - Ансамбль из 3 моделей: Random Forest, Gradient Boosting, Neural Network
   - Автоматическое извлечение 60+ признаков
   - TF-IDF векторизация текстовых данных
   - Поддержка онлайн-обучения на новых образцах
   - Кэширование предсказаний для производительности
   - Определение типа угрозы с оценкой уверенности

3. **Эвристический Анализ**
   - Определение типа угрозы по 13 категориям:
     - 🦠 RANSOMWARE (Шифровальщики)
     - 🔑 STEALER (Похищение данных)
     - ⛏️ MINER (Криптомайнеры)
     - 🎮 RAT (Удалённое управление)
     - 🪱 WORM (Сетевые черви)
     - 🤖 BOTNET (Ботнеты)
     - 🕵️ ROOTKIT (Скрытие в системе)
     - 📷 SPYWARE (Шпионское ПО)
     - 📢 ADWARE (Рекламное ПО)
     - 🐴 TROJAN (Трояны)
     - 📦 DROPPER (Загрузчики)
     - ⌨️ KEYLOGGER (Клавиатурные шпионы)
     - 💉 MEMORY_INJECTOR (Инъекция кода)

4. **Поведенческий Анализ**
   - Мониторинг действий файла в изолированной среде
   - Анализ системных вызовов API
   - Отслеживание сетевой активности
   - Контроль доступа к файлам и реестру

5. **Docker Песочница**
   - Полная изоляция анализируемых файлов
   - Эмуляция сетевой активности
   - Безопасное выполнение подозрительного кода
   - Автоматическое удаление контейнеров после анализа

6. **Многопоточное Сканирование**
   - Параллельная обработка файлов
   - LRU кэш результатов (10000 записей)
   - Прогресс-бары в реальном времени
   - Экспорт результатов в JSON/CSV

## 🛡️ Как Система Определяет Вирусы

### Уровень 1: Проверка Сигнатур

Система использует базу явных вредоносных паттернов:

```python
# Примеры детектируемых паттернов:
- CreateRemoteThread(NULL)           # Инъекция в процесс
- VirtualAllocEx(...PAGE_EXECUTE...) # Выделение исполняемой памяти
- WriteProcessMemory(...explorer...) # Запись в системные процессы
- RegSetValueEx...Run...\Temp\       # Автозагрузка из Temp
- URLDownloadToFile...hidden         # Скрытая загрузка
- CryptEncrypt...(locked|crypto)     # Шифрование файлов
- StopService...Windows Defender     # Отключение защиты
```

### Уровень 2: Эвристический Анализ

**Весовая система оценки:**
- Совпадение ключевого слова: +12 баллов
- Подозрительное поведение: +18 баллов
- Вредоносный API вызов: +15 баллов
- Подозрительное расширение: +10 баллов
- Сетевой индикатор: +14 баллов
- Бонус за множественные совпадения: +20 баллов

**Пороговые значения:**
- 0-30 баллов: CLEAN (Безопасный)
- 31-60 баллов: SUSPICIOUS (Подозрительный)
- 61+ баллов: MALICIOUS (Вредоносный)

### Уровень 3: Классификация Угроз

Для каждого типа угрозы система проверяет:

**RANSOMWARE:**
- Ключевые слова: `encrypt`, `decrypt`, `bitcoin`, `.locked`
- Поведение: массовое изменение файлов, шифрование
- API: `CryptEncrypt`, `DeleteVolumeShadowCopies`
- Сеть: `tor`, `onion`, `bitcoin`

**STEALER:**
- Ключевые слова: `password`, `cookie`, `credential`, `browser`
- Поведение: доступ к браузерам, копирование данных
- API: `CryptUnprotectData`, `sqlite3_open`
- Сеть: `pastebin`, `discord`, `telegram`

**MINER:**
- Ключевые слова: `pool`, `mining`, `cryptonight`, `stratum`
- Поведение: высокая загрузка CPU/GPU
- Сеть: `stratum+tcp`, `xmr-pool`

**RAT:**
- Ключевые слова: `remote`, `desktop`, `backdoor`, `c2`
- Поведение: прослушивание сети, создание процессов
- API: `socket`, `listen`, `CreateRemoteThread`
- Сеть: `no-ip`, `dyndns`, `ngrok`

### Уровень 4: Защита от Ложных Срабатываний

Система игнорирует паттерны в легитимном коде:
- Тестовые файлы (`pytest`, `unittest`)
- Фреймворки и библиотеки
- Системные утилиты
- Документация и примеры кода

**Признаки легитимного Python кода:**
- Наличие shebang (`#!/usr/bin/env python`)
- Импорты модулей в начале файла
- Определение классов и функций
- Обработка исключений (`try/except`)
- Использование логирования

**Для ПОДОЗРИТЕЛЬНЫХ файлов:**
> ⚠️ Будьте осторожны. Файл содержит подозрительные элементы. Рекомендуется дополнительная проверка.

**Для ОПАСНЫХ файлов:**
> 🚫 НЕ ИСПОЛЬЗОВАТЬ! Файл содержит вредоносный код. Рекомендуется поместить в карантин или удалить.

## 🗂️ Карантин

**Принцип работы:**
1. Файл копируется в защищённую директорию `quarantine/`
2. Оригинальный файл удаляется или перемещается
3. Файл переименовывается в формат `<timestamp>_<original_name>`
4. Доступ к файлу блокируется до восстановления

**Функции:**
- Просмотр всех помещённых в карантин файлов
- Информация о причине помещения
- Возможность восстановления
- Безвозвратное удаление

## 🔒 Безопасность

### Меры Предосторожности

1. **Изоляция**
   - Все подозрительные файлы анализируются в Docker контейнере
   - Контейнер автоматически уничтожается после анализа
   - Нет доступа к хост-системе

2. **Карантин**
   - Файлы хранятся в зашифрованном виде
   - Требуется подтверждение для восстановления
   - Журналирование всех операций

3. **Защита от Ложных Срабатываний**
   - Многоуровневая проверка
   - Whitelist для легитимного кода
   - Контекстный анализ паттернов
